# 小红书发文与复盘约定

记录日期：2026-09-07。用户要求将本轮发文经验沉淀进项目。

## 项目采用的原则

批量制作、分批发布。以解决不同搜索问题为目标，不用发文数量代替内容价值。下述节奏是本项目的试行方案，不是平台安全阈值，也不保证曝光或免于风控。

18–20篇是选题库存，不要求一次连发，也不要求在同一补丁内全部发完。补丁变化时重排选题，过时内容先更新、合并或撤出待发队列。

## 发布节奏（试行）

1. 先以每天1篇、累计5–7篇作为第一轮观察。未达到内容与核验要求时可以空缺，不为日更凑篇。
2. 每篇需有独立问题和已完成的图片、文案核验；给真实评论回复和数据记录留出时间。
3. 内容成熟且确有版本更新需求时，再评估一天2篇；分开安排即可，不设“随机间隔模拟真人”的做法。
4. 不同轮次尽量只调整一个主要变量，例如封面信息层级或标题切入点，便于解释结果。
5. 平台出现频率限制、验证码、审核或违规提示时，停止重复提交，按正常提示处理；不得换通道规避限制。

本文件只记录编辑与复盘方法，不创建自动化、不执行排期、不扩大任何发布授权。

## 正文与标签（2026-09-19用户明确要求）

- 后续笔记正文按玩家的需要来写：版本怎么玩、什么来牌和装备能选、站位与运营怎么处理。去掉“补进了某阵容、重写了某页、这次做了哪些修改”等创作者视角的制作过程。
- 数据来源、样本范围和适用条件仍要交代清楚；不虚构本人实战或把条件玩法写成无条件上分。
- 打标签时先在编辑器输入 `#金铲铲`，看自动推荐里的浏览量，优先点击内容相关且浏览热度高的标签。按每次实时推荐选择，不机械复用旧标签或旧浏览量。
- 每个话题都通过推荐项绑定并回读实体；不把粘贴的 `#标签` 文本当作绑定完成，不堆无关热门词，也不为凑数添加标签。

## 搜索选题与去重

- 一篇解决一个主问题。例如“裁决转给谁”“羊刀海妖如何选阵容”“某海克斯改变哪条玩法”。
- 可复用同一UI，但阵容、条件、装备归属、运营决策等内容必须有实质差异。
- 不将同一张图只换颜色、标题、词序或关键词后再次发布。
- “青龙刀／朔极之矛”“裁决转／裁决使纹章”等别名归入同篇，不按别名拆篇。
- 标题保留最重要的组件与阵容名，其余准确名称和别名在正文自然覆盖；封面先看得懂阵容，再辨认关键组件。
- 不堆无关热门话题，不捏造本人实战、胜率、当前最优或无条件上分承诺。
- 海克斯只有明确改变成型条件、运营路线或装备选择时才独立立篇；普通通用推荐并入阵容篇。
- 已发布内容需要实质更新时优先修订，说明适用补丁；不要因单篇低浏览反复删除重发。

## 发布后复盘

建议在发布后约24小时、72小时、7天记录。它们是观察窗口，不是平台推流周期，也不是自动提醒配置。

| 记录项 | 使用方式 |
|---|---|
| 笔记链接／ID、实际发布时间 | 有平台提交结果才记录为已提交；审核通过与公开可见分别按证据记录 |
| 标题、主问题、关键词、图片版本、游戏补丁 | 确定比较的是哪一版内容 |
| 曝光／阅读 | 按后台实际字段原样记录；缺失写“不可得”，不记成0 |
| 收藏、评论、关注等可见指标 | 使用相同观察窗口比较；如算比率，明确分母，不混用曝光与阅读 |
| 搜索来源或搜索词 | 仅记录后台实际提供的信息，不因某次手动搜不到便断言未收录 |
| 真实提问与错误反馈 | 找到攻略没有回答的问题、容易误解的条件和需要纠正的信息 |
| 审核／违规／限制提示 | 保存具体提示和处理结果，区别于单纯数据低 |
| 本轮判断与下轮变化 | 一次选一个主要改进项，避免同时改标题、封面、内容后无法归因 |

低浏览本身不证明风控，也可能与选题需求、封面表达、内容准确性或样本不足有关。优先依据平台通知判断限制；有错误先纠错，不为维护数据而保留误导内容。
