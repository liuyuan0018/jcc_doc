# 前排主片：文案与节奏重设计

系列条件以[七期规则](前排系列-七期规则-20260919.md)为准：统一5人集火、33%重伤、双抗各降低30%，按4种普通／神器组合与3种光明版分别比较。本文继续作为讲述结构草稿，具体名单和数值在各期结果review后填写。

本稿确定主片怎么讲。排序范围为全部24位前排，由侧边任务处理；暂沿用主片四位同屏的讲述结构，具体出镜对象等排序结果后再定。本文不计算、引用或预设新版名次；【】中的英雄和数值等结果确认后填写。淘汰动效已接入渲染器并提供独立旧回放预览，尚未制作新版口播与正式主片。

## 旧版为什么难懂、显得慢

核对对象：[主片第四版](../exports/frontline-video-main-v4/01-hero-pressure-final.mp4)及其[配音配方](../exports/frontline-video-main-v4/recipe.json)。

- 没讲清楚怎么算赢。旧稿说“重伤、减抗都挂上，每轮重新开打”，却没说“撑满30秒才能继续加伤害”。观众看到所有人最后都倒了，容易不知道名次从哪来。
- “加点压力，再来”“接着看护盾能撑多久”没有交代这一轮增加了多少伤害、要比较什么。
- 等待太长。全片41.8秒，旁白片段合计19.51秒；其余22.29秒没有旁白片段，仍有配乐。两处句间空档分别约4.75秒、4.71秒。这个统计来自配方，不能替代实际试听。

## 新版只讲清一件事

**每个英雄用自己的最强配置；每轮满血重新打，撑满30秒就继续加伤害。能扛住更高伤害的，排在前面。**

比较范围按当期装备件数限定：第1—4期为普通装备／神器，第5—7期为对应的光明版；海克斯按现有模型的合法适用分支选优。各英雄的装备、海克斯和羁绊可以不同，来伤条件相同。“最强”限定在本期模型和搜索范围内，不扩展成实战胜率结论。

## 口播草稿

下面按四位英雄、三个淘汰节点写。若结果并列或同轮多人失败，按实际结果合并节点，明确说并列，不硬分名次。

【第N名】只是写稿占位。正式字幕和配音使用具体英雄名，如“龙龟没撑到三十秒”，不会直接读出占位符。

| 段落 | 口播 | 画面要表达什么 |
| --- | --- | --- |
| 开场 | 这四个前排，各用各的最强配置，谁最能扛？ | 保留4秒封面；展示本期四位英雄。 |
| 规则，进入第一轮 | 每轮满血重开，撑满三十秒，就继续加伤害。 | 常驻“撑满30秒过关”；首轮写清“敌方每秒伤害【数值】”。 |
| 首个淘汰 | 【第四名】没撑到三十秒。 | 死亡发生后再说；该行变灰并标“已淘汰”。 |
| 第二轮开始 | 每秒伤害加到【第二轮数值】。 | 剩下三位满血重开。已淘汰者保留灰色结果，不再重复播放死亡。 |
| 第二个淘汰 | 【第三名】也没撑住，还剩两个。 | 对应死亡发生后再说。 |
| 第三轮开始 | 再加到【第三轮数值】，看谁能撑住。 | 两位在相同伤害下比较。 |
| 分出胜负 | 【第二名】倒了，【第一名】撑满三十秒。 | 等失败事件发生、另一位确实走完30秒后说；必要时拆成前后两句。 |
| 结尾 | 这组测试【第一名】最能扛，每秒【第一名最高通过值】也能撑住。 | 展示完整排名、各自配置和最高通过值；标清数值是敌方每秒伤害。 |

主片不再逐项念重伤、减抗、星级和人口。关键条件放在固定说明区，完整参数留在配文；不能为了简短而把不同承伤条件混成同一组。

## 画面和节奏怎么改

- GUI沿用当前常规榜、冷门榜的浅紫底、深紫字、亮紫强调、白色卡片与苹方字体；提示色用暖橙。已接入[统一主题配方](../scripts/tank-video/theme-notes-purple.json)，本轮效果预览采用该主题，正式主片与封面后续统一使用。
- 先交代“30秒过关”，再让观众看血条。不要等结尾才解释排名标准。
- 伤害数值用“敌方每秒伤害”标注，小字注明“减伤前”；模拟倒计时明确写“本轮剩余”，避免与视频播放秒数混淆。
- 每次换轮明确显示“满血重开”。同一轮仍按同一时间倍率同步播放所有参赛英雄，不单独加速某个人。
- 已淘汰者不再参赛。胜负分出后直接给结果，不为凑四轮再安排冠军死亡。冠军的最高通过值来自侧边任务结果，结尾可直接展示。
- 原版每轮固定播放和停留的安排重新按事件排。优先删掉没有信息的等待，关键死亡、通过30秒和名次揭晓留出看清时间。
- 暂以约28—32秒为剪辑目标，不先锁死时长；数据若不支持三个独立淘汰节点，就减少轮次。

## 淘汰瞬间的表现

第五版3秒淘汰动效及当前紫色GUI已获用户认可，后续主片沿用。认可范围为这段表现；新版名单、排名、口播和正式成片另行核验。

采用“血条归零 → 本栏横向冲击回弹并闪暖橙边 → 淘汰标记出现 → 变灰保留”的动效，总长3秒，起点绑定实际死亡帧。按“翻倍，加到3s”的反馈，将上一版1.5秒的各视觉阶段等比例拉长。已接入渲染器，[4秒效果预览](../exports/frontline-elimination-preview-v5/elimination-preview.mp4)沿用统一后的紫色GUI；使用旧回放，仅用于看界面和动效，不提供新版排名。参数保存在[动效配方](../scripts/tank-video/effects-elimination.json)。

| 相对死亡时刻 | 表现 | 目的 |
| --- | --- | --- |
| 0—1.6秒 | 仅该栏横向冲击并回弹，位移逐次减小；1080宽画面最大18像素。暖橙外框在1.5秒内淡出。 | 保留已加大的幅度，并明显拉长表现；血条在真实归零后触发，不提前演出。 |
| 0.3—1.3秒 | 在该栏固定位置弹出“淘汰”标记，轻微放大后落定。 | 给状态变化留出识别时间；不遮住英雄名、装备和血条。 |
| 1.7—3秒 | 头像、装备逐渐去色，底板压暗；名字和结果保持清晰。 | 先看清淘汰动作，再变灰，后续维持灰色状态。 |

- 栏目保留原位置；其他栏继续同步播放，不随之抖动、暂停或重新排位。
- 这套表现每个英雄只触发一次，换轮后不再重复。若同一时刻多人淘汰，各栏按真实事件同时表现，不人为拉开死亡顺序。
- 已接入归零瞬间约0.1秒的短落点音，单独产轨，后续试听再决定是否调整；不改变现有配乐音量。同时淘汰多人时音效合为一次。
- 动效持续期间其他栏继续播放；如最后一段停留不足以播完动效，仅延长最后的结果前停留，不改变战斗数据或事件时刻。冠军标记等另一位确实撑满30秒、结果成立后再出现。

## 配音方向

- 沿用当前声线、已认可的人声处理和稳定音量配乐。开场封面暂保留4秒，仍须覆盖开场实测句尾。
- 下一轮先用比旧版明显快一档的语速做代表样音：原配方`+4%`，候选先试`+18%`。这是待试听的合成设置，不表示成片时长必然缩短14%。
- 英雄名与动作连着说，如“龙龟没撑住”，不读成“龙龟，没撑住”。一句只表达一个动作或结论。
- “提高语速”和“减少空档”一起处理。不要只把声音加速，却仍在原位置等四五秒。
- 新口播尚未合成、试听，现有正式成片未改动。当前动效预览只含淘汰音效，没有新增口播或配乐。

## 等排序结果后填写

只接收侧边任务确认的本期名单、各英雄配置、同条件排名、最高通过值与首次失败值；并列保留并列。接入时再核对对应回放和事件时间，不复用旧版名次或旧死亡时刻。

把【】全部替换成真实结果后，再确定完整口播和时间表。现阶段供 review 的重点是：**规则是否一遍能听懂，淘汰过程是否清楚，结尾是否直接回答谁最能扛。**
