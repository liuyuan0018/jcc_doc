# 蔚时序与减伤专项配置交接

目标：修复蔚动作、自增益、回蓝和治疗时序，使同一官方输入在 C++ 中得到与官方一致的战斗过程和最终结果。不能把自研前后差分、规则测试或合成对局跑通当成最终验收。

## 本包与另一台电脑

本包位于文档仓库 `liuyuan0018/jcc_doc` 的 `research/frontline-subtopics-20261017/N02-damage-reduction/version-comparison/`。引擎开发在另一仓库 `liuyuan0018/jcc`。所有下述引擎路径均相对 `jcc` 根目录；二进制和输出目录使用开发机本机路径，不依赖交接机的临时目录。

先读取开发机的 AGENTS.md、适用的战斗对齐契约及最新代码。核查基准是引擎提交 `34d86ac1516d0fad1c3627b4d904d139f75acdb9`；若最新代码已修复，先复核，避免重复改动。此包没有修改引擎和生产配表。

## 已复现问题与证据边界

用本包 18.3 输入运行默认原生 CLI 时，二星蔚携普通振奋、挂满 6 主宰，对手攻击力 1000、攻速 1.0、暴击率 0。该合成输入的 tickRate 为 30，仅供定位现有模型行为，不能拿这个时钟反推官方秒数。

- 现有技能开始／释放／结束 tick 为 70/76/88、135/141/153、200/206/218、265/271/283。
- 自增益在 76 施加，预计到期 166；141 又刷新至 231，206 刷新至 296，271 刷新至 361。
- 自增益仍在时，受击回蓝在 99、129、159 各增加 21，进而发生再次施法，影响主动治疗次数、攻击治疗次数、血线和振奋按当前已损生命计算的动态治疗。

这些数字是自研诊断轨迹，不是官方预期值。默认配置中，主宰成员 `damageReduction.set` 还会覆盖装备／技能减伤；没有主宰时振奋 8% 与技能 15% 被相加为 23%。这些是独立问题，不能通过伪造时间线、最终血量或胜负绕过。

## 修复与官方验收

1. 用 REA 提取并固定目标官方对局的种子、JCE 初始状态和 lockstep 输入帧流，记录来源、内容哈希、包／规则身份和实体／配置 ID 映射。优先选择包含蔚施法、自增益和治疗的样本；没有消费所需输入时明确列出缺口，不能把本包合成输入改称官方输入。
2. 按既有 BattleSystem、Buff、状态与 Action 分层修复真实机制。保留定点／整数及官方时钟语义，避免在主循环增加蔚专用假计时器。配置改动遵循引擎仓库现行配表流程。
3. 官方输出不得参与模拟输入、驱动、事件回填或运行中修正。独立运行结束后才加载官方输出，逐帧比较状态及事件，报告首个分歧帧、实体、字段／事件、双方原值和定位证据；继续修复直至目标对局过程与结果一致。
4. 同时验证锁贡献生命周期、四类普通回蓝入口、同级刷新、到期／死亡、治疗顺序及次数、攻击事件与增益窗口。组件测试用于定位和回归；官方同输入对齐才是验收。
5. 修复后再用本包 18.3 与 latest 两套参数重跑同一诊断场景，确认除了明确版本参数外的输入一致。参数替换实验本身不是两个官方历史版本的回放验证；定量结论须说明已验证的机制和规则身份。

交付修改文件、构建与回归结果、官方样本身份／输入映射、过程与结果比较、首个未解分歧及尚缺证据。尚未完成官方对齐时如实标注，不能宣称已完成或已全量对齐 18.4。
