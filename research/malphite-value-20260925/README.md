目标：比较2/4/6黑荆棘、10档坦克献祭、普通三件装备与适用海克斯的投入收益，寻找较低投入接近较高投入的方案。

- 预计250,950组，实际数量待合法装备池核对。未开始全量模拟。
- Main三轮各8套；从全量结果选择24套，不能用出镜数限制配装枚举。
- Results展示24套出镜配置加64套不重复精选，共88条、11页，按同一评分排序并保留全量真实名次。
- 每行detailRichText为通用展示字段，本期承载黑荆棘档位与献祭费用星级；海克斯沿用现有图标槽。
- 普通三件出装枚举不变，第四件为普通装备条目，hiddenInUi=true。候选装备内的hp包含羁绊固定生命，不再在别处重复添加；hpp为百分比生命。
- 购入成本、可出售价值、羁绊占位分开呈现，不构造未定义的综合性价比分数。候选文件仅列购入成本，卖价尚未核对。

## 当前证据边界

现有模拟器24位英雄不含墨菲特，需要新增模型。model-source.json保存两星基础属性、技能及魔岩巨兽来源和哈希。魔岩巨兽按5人集火应提供50双抗，不能遗漏。

sacrifice-items.candidate.json为30件待核验候选装备，来自TFTips数据表；来源明确声明乘算尚未对照游戏。未作为正式战斗输入。

仍待确定：献祭乘算及百分比生命的叠加口径；石化期间普攻/回蓝，护盾自然到期是否触发波动。完整25万组应在模型口径锁定后启动，避免批量生产错误结论。

## 计算代码

当前tank-lab/src/prepare_engine.py生成可变长度Build.ids，makeBuild累加Item.hpp并接受kind=-1的纯属性装备；三槽旧调用保留兼容重载。web.cpp保留34/35参数输入，并支持第36项起附加装备索引。generated.hpp的Item追加hpp、hiddenInUi默认字段，ITEMS支持启动阶段注册新条目；扫描期间禁止修改装备注册表。生成旧catalog时不得覆盖扩展字段。

冻结输入哈希一致；新旧30条件的排列完全一致，但30项分数均改变。独立Python简化模型未调用C++公式实现，针对三振奋无海克斯、双振奋板甲单身板甲、振奋板甲狂徒无海克斯，在30条件各测细分成绩及下一点，共180次；生死、死亡帧、施法/普攻次数、最大生命、治疗、护盾吸收与冻结C++相符。这只验证声明假设下的实现一致性，不证明游戏机制正确。献祭生命叠加及乘算、多振奋治疗结算、单身板甲生命与献祭叠加仍缺游戏实测佐证；暂停视频制作，不把本轮模型最高成绩表述为游戏最优解。详见 exports/frontline-malphite-v1/audit-v1/。
